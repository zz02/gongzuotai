# 点灯自媒体工作台：产品重审

日期：2026-10-13

状态：设计评审稿，未启动本版原型或正式功能开发。

规则主文档：[PRD 1.5](PRD-点灯自媒体工作台.md)。本文说明取舍和页面形态，不另设一套业务规则。

## 一、先回答：这个工作台到底帮你什么

它要帮助“点灯的曾曾”用每周 18～22 小时，持续做出 AI 职场新手愿意看、能照着做、还想继续看的图文，并根据真实发布反馈决定下一篇。

用户不应该先研究几十个 Skill，也不应该每天先翻完三个资讯源。打开后应能回答三个问题：**我现在做什么？这篇还缺什么？做完如何判断值不值得继续？**

已有的五步制作流程保留，但产品必须补齐发布后的反馈：

```text
三类信源＋本人经验＋OB 材料
             ↓
       判断选题是否值得做
             ↓
     同一作品内：稿件 → 图文 → 成品
             ↓
       人工发布、登记实际版本
             ↓
       记录数据和读者真实问题
             ↓
       确定一项下次尝试 → 回到选题
```

“三个月净增 20,000”作为挑战目标保留。它不能成为生成篇数或批量铺量的理由，也不能由软件承诺。50 是此前提供的三平台历史合计，启动计划时需重新确认基线及日期。

## 二、重新审视后，真正需要改的地方

依据为现有代码盘点、创作能力注册、Skills 同步脚本、现有 PRD 与原型；不是对线上可用性的重新验收。具体代码索引见[功能盘点](代码功能盘点-2026-10-12.md)。

| 问题 | 产品判断 | 本版取舍 |
|---|---|---|
| 看见资讯就能转稿，但用户不知道为什么值得做 | 热度解决发现，不解决定位与差异 | 先比较读者问题、本人贡献、材料和投入，再立项 |
| 文档写了很多能力，但页面仍可能只有按钮和生成记录 | “能调用”与“拿到成品”之间还差编辑、确认、图片和导出 | 以单个作品承接结果，不能跳去另一个助手找正文 |
| 三个平台容易被理解为一键复制三份 | 读者场景和阅读结构不同，复用的是事实 | 首先做公众号与小红书差异化成品，抖音图文第二批 |
| 发布复盘藏在辅助视图 | 不复盘就无法改进下一次选题 | 提升为左侧主入口，保留发布快照与下一步尝试 |
| Skill 数量增加，但没有清楚的调用条件 | 多装几个方法不自动改善内容 | 各环节选推荐方法，声明输入、结果和失败处理 |
| 主题只有配色，壁纸必须自己找图 | 不符合“点着就换”的期待 | 内置真实壁纸缩略图，点击应用、自动保存、可撤销 |

本版不删除或折叠隐藏 RedFox 原有能力。其热榜、搜索、详情、追踪、创作改写、检测、封面、收藏与设置继续走原操作路径；三个主信源分别保留。新流程只接走用户明确选中的材料。

## 三、内容定位不是一句“AI 博主”

建议持续回答：**普通职场人遇到一个具体任务，怎样用 AI 做出合格结果，哪里仍要自己判断？** 产品背景是优势：说明适用场景、比较取舍、指出失败边界。

先验证三个栏目，而不是同时运营十种选题：

| 栏目 | 读者得到什么 | 本人需要提供什么 | 为什么会继续关注 |
|---|---|---|---|
| 职场点灯 | 一个工作任务的可执行做法 | 操作过程、输入示例、可核对结果 | 下次遇到相似任务还找得到方法 |
| 实测避坑 | 判断工具何时好用、何时别用 | 正反例、失败过程、适用条件 | 获得可信的选择依据 |
| 带走一招 | 一张清单、一段提示词或一套判断步骤 | 明确使用条件及示例 | 小成本获得可复用的方法 |

“女生友好”落实为清楚、尊重、不预设技术知识和审美友好的表达，不变成只推粉色、无关美女封面或制造年龄焦虑。封面好看只是入口，正文必须兑现承诺。

## 四、每天怎么用：五个关键页面

Purpose：让个人作者独立完成制作与复盘，减少找入口和重复搬运。

Tone：温暖、清爽、内容优先；装饰集中在欢迎区与背景。

Differentiation：一张作品卡贯穿材料、平台成品和反馈，用户始终知道正在改哪篇。

页面模板：概览看板、比较列表、双栏编辑、详情复盘、图库配置。沿用 PUI 基础控件，先验证交互再细化高保真。

以下为业务线框，文字和示例不代表实际账户数据或已生成结果。桌面固定左栏，窄屏保留左侧可展开导航；不把五个步骤和三个平台混成八个同级页签。

### 1. 创作首页：只突出一项下一步

```text
┌──────────┬──────────────────────────────────────────┐
│ 点灯工作台│ 点灯的曾曾                     换壁纸    │
│ 创作首页 ●│ 欢迎区：可见壁纸，文字使用清晰遮罩        │
│ 信源     ├──────────────────────────────────────────┤
│ 选题库   │ 继续作品：AI 做竞品对比                  │
│ 我的作品 │ 下一步：补一张结果核验截图   [补充材料]   │
│ 发布复盘 │ 公众号：待补材料  小红书：待补材料        │
│          ├──────────────────────┬───────────────────┤
│ RedFox   │ 待复盘作品           │ 候选选题          │
│ 原有入口 │ 到期日期／观察窗口   │ 最多三个及理由    │
│          │ [记录反馈]           │ [比较选题]        │
│ 素材库   ├──────────────────────┴───────────────────┤
│ Skill中心│ 无作品：从一个问题开始  [新建作品]        │
│ 外观设置 │ 不要求先连接全部服务或填写账号数据        │
└──────────┴──────────────────────────────────────────┘
```

继续作品回到原步骤。生成失败显示重试与手写，登录失败不清空内容。首次进入沿用已知定位，OB 与样稿可后补。首页不放无数据的增长曲线，不让服务配置抢走创作主位置。

### 2. 选题比较：从“很多题”变成“做哪一题”

```text
选题库                                  [手写选题]
候选一              候选二              候选三
读者遇到的问题      读者遇到的问题      读者遇到的问题
能获得的结果        能获得的结果        能获得的结果
本人贡献／证据      本人贡献／证据      本人贡献／证据
还缺什么／预计投入  还缺什么／预计投入  还缺什么／预计投入
建议：值得做        建议：先补材料      建议：暂不做
[开始创作]          [补充材料]          [暂存选题]
```

示例：“某 AI 新模型发布”仅有新闻，不足以直接写成亲测推荐；“用它整理会议待办，会漏掉什么？”有具体读者问题，但仍要补测试输入、截图与漏项。工作台应提示差距，允许先保存准备稿，不编造亲测经历。

立项后材料自动带入作品。同一资讯重复转入回到原选题；明确选择另一个角度才新建。推荐判断可修改，但未解决的事实缺口不能因此消失。

### 3. 作品编辑：能写、能改、能看结果

```text
作品名称                         已保存    [查看素材]
生成稿件 ───── 图片排版 ───── 发布成品
公众号 │ 小红书 │ 抖音图文
┌─────────────────────────────┬─────────────────────┐
│ 标题／封面文字／开头，三组候选│ 手机阅读预览        │
│ [采用方案]                  │ 当前平台真实正文    │
│                             │ 当前页图片和文字    │
│ 正文编辑                    │ 不是固定示例文章    │
│ 本人原话、结果、操作与限制    │                     │
│                             │                     │
├─────────────────────────────┴─────────────────────┤
│ 待处理：一处承诺缺证据  [定位问题]  [确认文字]       │
└───────────────────────────────────────────────────┘
```

写作开始前，用已选材料补充“我实际做了什么、我的判断是什么”。已有文章直接导入为候选，不强制从零填写长表单。正文在当前平台里出现，公众号失败不清空小红书，也不要求整批重跑。

图片阶段改为“页面顺序／当前画面／制作选项”布局：先看逐页内容，再选择真实截图、文字模板或 Codex 配图。操作教程优先用真实截图，概念解释再用插图，不能让好看的假界面冒充实测。重做一页只影响这一页，标题变化提示检查封面。

发布成品页展示公众号整篇预览、小红书整组预览及缺件清单。缺封面、缺页或图片不匹配正文时不能显示成品齐全；可保存草稿。导出后仍是待发布，人工登记才建立发布记录。

### 4. 发布复盘：给下一篇一个明确方向

```text
发布复盘   待发布 │ 已发布 │ 复盘记录
平台：小红书    栏目：实测避坑    窗口：发布后 7 天
┌────────────────┬──────────────────┬────────────────┐
│ 实际发布快照   │ 本次观察          │ 下一次尝试     │
│ 标题、封面     │ 观察时间          │ 已知现象       │
│ 成品版本       │ 阅读／收藏／评论  │ 可能解释       │
│ 发布时间       │ 归因关注：未记录  │ 还不知道什么   │
│ 原文或备注     │ 真实评论与来源    │ 只选一项改进   │
│                │ [保存记录]        │ [创建选题]     │
└────────────────┴──────────────────┴────────────────┘
```

缺数据显示“未记录”，不当成零。两个不同平台的阅读不合并成总成绩，两个不同作品不能直接声称某种封面造成了涨粉。先记录观察，再提出假设；用户采纳后形成下一篇要验证的点。

数据来源先采用人工录入或本人粘贴。尚未验证三个平台登录后的数据字段与开放接口，不把自动拉取账号、评论或粉丝归因当首版已具备能力。

### 5. 外观图库：真图片，点一下就换

```text
外观设置                  精选壁纸 │ 我的收藏 │ 我的壁纸
┌──────────────────────┬────────────────────────────────┐
│ 当前工作台预览       │ 林间晨光   海盐云朵   暖光书桌 │
│ 含左栏、标题、正文卡 │ [图片缩图] [图片缩图] [图片缩图]│
│                      │ 樱花窗边   星夜山脊   可爱伙伴 │
│ 显示手机裁切         │ [图片缩图] [图片缩图] [图片缩图]│
├──────────────────────┴────────────────────────────────┤
│ 配色跟随套装：开   [调整显示] [上传壁纸] [恢复默认]    │
│ 点击图片即应用并保存；完成后显示“已更换，可撤销”       │
└───────────────────────────────────────────────────────┘
```

至少六张随产品提供的壁纸，无需外链加载。五套推荐配色随套装变化，也可独立选择。裁切和遮罩微调才需要保存／取消；常用换图不增加确认步骤。快速连点保留最后选择，失败恢复上一套。

内置优先原创与可分发图片；喜欢的迪丽热巴、奶龙图片上传一次后进入个人图库，之后也是点击切换。恢复默认不删图库。壁纸不进入模型、不进入成品、不跟随代码上传 GitHub。

## 五、Skills 应该怎么出现在创作里

推荐的是“完成什么”，不是“崇拜哪个作者”。保留 db、卡兹克、花叔、宝玉、归藏、乔木等既有能力分工；云舒的方法补缺口，不把已有方法全部替换。

| 用户遇到的问题 | 建议动作 | 方法组合与限制 |
|---|---|---|
| 有零碎体验，说不出观点 | 整理想法 | 云舒思维挖掘保留本人表达，不能补造经历 |
| 一个题目不知道怎么写 | 梳理结构 | 云舒写作阶段引导＋现有卡兹克写作适配；先得到结构，确认后成稿 |
| 标题空泛、开头绕 | 检查标题 | 现有 db 方法，结合标题、封面、开头与正文兑现位置 |
| 内容像拼凑资讯 | 检查内容 | 核对本人贡献、证据、可执行步骤，再处理空话；不追求虚构 AI 率 |
| 不知道配图选什么风格 | 选择风格 | 云舒配图助手的样张与逐图计划＋Codex 执行，结合宝玉逐页方法 |
| 需要参考真实工具案例 | 查找案例 | 云舒案例雷达；引用真实链接，浏览器依赖补齐并验收后再接入 |
| 资料太长难以阅读 | 阅读资料 | 云舒可读长文只用于阅读整理，不当公众号发布排版引擎 |
| 希望越用越像自己 | 保存偏好 | 本人确认的手改＋花叔女娲方法，沉淀个人规范，不自动学习每处修改 |

本机安装与工作台适配是两件事。本次安装八项能力，完整版本、目录与依赖见[安装记录](云舒Skills安装记录-2026-10-13.md)。Skill 中心后续需明确“仅有来源／已适配／已验证／已停用”，不得因文件存在直接显示已验证。

OB 继续承担长期知识：选中的原笔记只读引用，作品与复盘可以确认后归档为独立快照。工作台承接当前稿，不让用户面对两个会相互覆盖的正文主版本。

## 六、90 天怎么验证，而不是怎么承诺

启动日期待确认，下表只表达阶段长度，不编造日历或粉丝里程碑。

| 阶段 | 核心问题 | 需要积累的证据 |
|---|---|---|
| 起步验证，14 天 | 能否独立做出两次不同主题的合格图文？ | 两套真实成品、平台后台预览、主动耗时与返工记录 |
| 栏目验证，28 天 | 哪些问题和表达值得继续做？ | 同平台同窗口的数据、真实评论、各栏目样本数量 |
| 集中改善，48 天 | 如何把已经得到反馈的内容做得更稳定？ | 系列内容、单项改进记录、持续关注与粉丝快照 |

20 小时的一周参考：选题研究 2、实测 5、主稿 3、平台适配 2、图文 3、发布互动 2、复盘 1、缓冲 2。先尝试一个实测主题生成一篇公众号，再形成一篇教程型和一篇轻量问答型小红书；抖音图文按精力接入。两篇不能只是相同内容换标题，缺少独立价值就少发一篇。

工作台首先降低搬运、重复改图和找材料的时间，不能替代真实体验、持续学习和读者互动。每周只验证一个改善假设；没有足够数据时继续观察，不用一次表现差就改定位。完整指标口径见 PRD 4.3。

## 七、设计评审与后续开发的门槛

本次交付只包括设计文件、规则修订和授权安装。没有更换线上页面，没有制作内置壁纸图片，也没有把新 Skills 接到生产调用。

后续按下面顺序推进，不能以“按钮已经可点”代替通过：

1. 先评审本版页面职责、选题判断和发布复盘是否符合实际工作。
2. 再更新隔离交互原型，覆盖两个不同主题、失败恢复、局部采用和一键壁纸。
3. 原型通过后实施公众号与小红书真实制作链路；核对全部 RedFox 旧入口无退化。
4. 用本人素材完成两次独立制作，检查图片、复制排版、成品文件、刷新续写和 OB 归档。
5. 真实发布并有观察数据后，再判断运营复盘有没有帮助改善下一篇。

首轮建议用“AI 整理会议待办的漏项核对”和“AI 竞品对比的依据核查”两个题。它们是验收场景，不是默认塞进任何作品的固定文案。具体发布日期、真实材料和内容判断由作者掌握。

### 本轮自检

| 检查项 | 结果与边界 |
|---|---|
| 用户与目标 | 沿用已确认定位、时间和平台；历史粉丝数与启动基线分开 |
| 跨页面一致性 | 五步制作不变，新增明确的反馈回路；成品交付与发布登记分开 |
| 交互闭环 | 为选题、失败、保存、复盘和壁纸分别写出下一步与恢复行为 |
| 原功能保护 | RedFox 全部原能力与三主信源保留，未修改生产代码 |
| 技能可用性 | 八项已安装；环境检查与实际执行分开，保留个人写作助手 |
| 开发可交付性 | PRD 更新页面目标、状态与验收；本附件给出关键线框，未假称高保真已完成 |
| 尚待验证 | 新原型、真实壁纸、能力接入、两次真实制作和运营结果均尚未验收 |
