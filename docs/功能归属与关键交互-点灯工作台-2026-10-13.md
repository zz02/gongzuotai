# 点灯工作台：功能归属与关键交互

更新日期：2026-10-15。状态：功能归属与交互评审稿；[隔离原型](prototypes/creator-flow-v1/index.html)仅供评审，未开发正式功能。覆盖范围与缺项见[本轮验收](交互原型验收-统一创作-2026-10-13.md)。

本文是本轮功能归属与交互的唯一评审入口，替代旧版的五步强制流转和重复导航方案。它不是已经完成验收的开发 PRD；确认后再补对应原型、截图和实现细则。

## 1. 产品结构：三个工作入口，一个内容编辑器

服务「点灯的曾曾」的个人图文创作：外部发现、个人积累、内容生产。面向 AI 职场新手，适配公众号、小红书和抖音图文；帮助稳定产出和根据反馈改进，不承诺涨粉数量。

| 左侧入口 | 进入后看到什么 | 主要动作 |
|---|---|---|
| 内容创作 | 最近编辑的内容；全部、选题、草稿、待发布、已发布筛选 | 新建内容、继续编辑、查看成品 |
| 信源 | RedFox、AIHOT、乔木 RSS 三个明确分组 | 浏览检索、查看详情、收藏材料、用于创作 |
| 知识库 | OB 笔记、已收藏资料、图片等附件；保留其他既有连接 | 搜索预览、引用材料、导入正文 |

默认进入内容创作，不新增独立首页。左侧下方保留 Skills 中心、助手、设置；壁纸由右上角快捷入口打开。筛选视图不是新的内容库，也不是必须依次完成的流程。

```text
外部资讯 ─┐
OB 笔记 ──┤
个人选题 ─┼── 新建内容／加入已有内容 ── 同一编辑器 ── 平台成品
已有文章 ─┤                              │              │
空白写作 ─┘                         写稿、配图、排版   发布记录与反馈
```

## 2. 现有功能归属：合并入口，不删能力

| 现有功能 | 新归属 | 保留与融合方式 |
|---|---|---|
| RedFox 热榜、关键词趋势、同步 | 信源 → RedFox | 保留平台、筛选、缓存、定时与调用确认；不改原取数逻辑 |
| RedFox 搜索、作品详情、评论相关能力 | 信源 → RedFox | 保留原详情与分析操作；只调整导航和创作衔接，不把评论数量冒充评论全文 |
| 账号追踪、同步、诊断、趋势 | 信源 → RedFox → 账号追踪 | 保留追踪分组、历史作品和诊断；不等同于本人账号发布授权 |
| AIHOT、乔木 RSS、辅助官方频道 | 信源内对应分组 | 保留独立加载与错误提示；不因一个来源失败清空其他来源 |
| 灵感选题、收藏、状态、反馈、回收站 | 内容创作 → 选题视图 | 统一查询入口，保留原历史与操作；开始写作后可回查选题依据 |
| 外部收藏、OB 笔记与其他知识连接 | 知识库 | 统一发现与引用，不将全部 OB 笔记复制到工作台；原创建、分析、保存能力继续保留 |
| 新工作台与原创作、改写 | 内容创作 → 编辑器 | 统一正文落点；保留旧创作方法、风格和热点关联，避免两个正文编辑入口 |
| 违禁词检测、发布检查 | 编辑器 → 检查 | 两类能力分别显示来源与边界，不用新审稿替换旧检测 |
| 原封面、生图、模板文字卡片 | 编辑器 → 配图 | 保留不同制作方式，不把模板导出标成 AI 生图 |
| 公众号排版、小红书及抖音图文 | 编辑器 → 平台版本 | 正文、图片与成品预览放在当前版本内；无需离开稿件 |
| 原 Markdown 文件项目 | 内容创作 → 历史内容筛选 | 可查看原项目、执行记录与采用结果；导入先预览，不凭标题自动合并 |
| 成品导出、发布登记、反馈 | 当前内容 → 发布记录 | 跟随平台版本，不另建发布库；跨内容记录可在已发布视图汇总 |
| 视频与现有合成入口 | 内容创作内的更多工具 | 保留原入口和历史，不要求做完视频才能交付图文，本轮不扩建 |
| 创作方法、RedFox Skills、Hub、自定义、模板 | Skills 中心 | 保留来源更新、查看、编辑、模板生成、安装管理和热榜绑定；不强制统一成一种运行方式 |
| Agent 对话 | 助手 | 保留聊天与任务记录；写入正文前必须选择目标并确认采用 |
| 我的账号、赛道、风格和创作档案 | 设置 → 账号与表达 | 编辑器可选用现有档案；个人规范不被上游默认风格覆盖 |
| 定时、通知、凭据、模型依赖 | 设置内对应分组 | 原计划、额度及确认机制不变；换导航不触发新任务 |
| 登录、密码、备份、日志、诊断 | 设置内对应分组 | 保留会话、备份与历史，不重置账户；迁移前另验恢复能力 |
| 粉丝目标与投入记录 | 内容创作 → 已发布视图的运营概览 | 有数据再展示，未填不当零；不挤占编辑区域 |
| 原仪表盘 | 设置 → 更多工具中的原概览 | 迁移期保留旧链接，常用创作信息逐项归入上述入口，不直接删除旧统计 |

现阶段不迁移存储。后续迁移必须建立历史记录对应关系、保留来源与旧链接；一个旧记录只能有一个确认后的编辑落点。尚未迁移的记录明确标示原存储位置，不能显示成空库或再次复制建档。

## 3. 内容关系：能复用，但不重复建档

- **参考材料**是引用，不是文稿。多份材料能共同支持一篇内容，同一材料也能支持多篇不同角度的内容。
- **选题**是尚未展开的内容；可以只有一句话。开始写作沿用当前记录，不要求先补问卷或生成母稿。拆成不同角度时，明确选择“另建内容”，保留关联。
- **平台版本**分别保存标题、正文、配图和发布记录；改公众号不自动覆盖小红书。新增平台时预览要复用的材料与正文，再确认改编。
- **OB 原文**继续由 OB 管理。用于创作时保存引用快照与原笔记位置；只有“导入正文”才把选定内容带入编辑区。归档另存，不暗中回写原笔记。
- **发布版本**在登记时保留快照。后续修改形成修订，不篡改当时发布记录；整篇内容可以同时存在已发布平台和未完成平台，列表用平台状态说明，不硬判全篇已完成。

## 4. 关键交互：动作、反馈和结果都在原上下文

### 4.1 从信源或知识库进入创作

选择材料后点击“用于创作”，就地选择“新建内容”或“加入已有”。新建时只需确认标题和目标平台，默认不自动启动模型；加入已有时仅添加引用，不改正文。重复点击返回既有操作结果；同一材料另写不同角度须明确另建。

知识库另外提供“导入正文”：先预览内容，确认后写入空稿；已有正文时展示对比，允许复制选段或确认替换。不能用“引用材料”隐含整篇替换。

**验收场景**：已有公众号草稿，选两篇 OB 笔记并加入该稿，正文不变、引用可打开、OB 原文不变；取消选择不创建空内容。

### 4.2 内容列表与编辑器

内容列表按最近编辑排序，搜索标题并按平台、状态筛选；空列表提供“新建内容”和“导入文章”。旧项目在同处可查，必要时进入原项目查看，不制造重复卡片。

编辑器保持固定的内容标题和保存状态；平台版本在顶部切换。正文是主区，阅读预览在旁，材料按需展开。写作、检查、配图、排版、发布记录是当前内容的操作，不再与平台混成一长排同级页签。

可以手写、导入、请求建议或生成初稿，不以选题评估通过为前提。已读材料可以整理事实；未核验或未实测内容明确标注缺口，不自动写成亲测经历。

**验收场景**：仅有一句选题也能进入空稿并保存；切换平台再回来保留各自正文；保存失败显示“未保存”，离开前提示，不冒充成功。

### 4.3 Skills 调用与结果采用

在编辑器点具体动作，如“优化标题”，直接带入当前平台与所选正文；在 Skills 中心点“用于创作”，先选内容和平台，不能默默新建文章或启动生成。

调用前可查看所用方法、输入范围、结果用途及依赖；用户确认后才运行。不同任务分别显示等待、运行中、成功、失败，不画虚假的百分比。现有单任务限制下说明正在处理哪项，不能表现为全平台同时运行。

成功后在当前内容显示候选：标题建议可逐组选择，审稿建议可逐条采用，整稿可对比。放弃不改原稿；处理期间原稿已变化时，不允许旧结果直接覆盖。失败保留输入、原稿和已成功图片，只重试失败项。是否可取消以真实能力为准，不画无效取消按钮。

**验收场景**：生成标题期间用户修改正文，结果回来仍保留手改；用户不点采用，标题不变化；刷新后能重新找到任务与候选。

### 4.4 图片、排版与发布成品

在当前平台选择“上传图片”“模板图卡”或“AI 生图”。选择用途后再填图片要求；AI 生图确认提示词后执行，模板图卡显示可编辑文字，不混淆制作方式。

公众号预览包含标题、摘要、封面与正文配图；小红书和抖音图文预览包括有顺序的图片、标题及配文。单页重做不清空整组。正文更新后提示相关旧图片需要核对，不自动判为匹配。

导出前展示实际文件清单。缺图、生成失败或只有 HTML 时直接说明缺项，不能宣称完整图片包。用户可以继续编辑或导出已有材料，但不标记为完整成品。最终内容由本人核对，辅助检查不保证平台审核通过。

**验收场景**：一组图只有一页失败，成功页仍可预览，重试只处理失败页；成品文件能打开且图片顺序与预览一致。

### 4.5 发布反馈与知识归档

复制或下载不等于发布。人工发布后登记平台、链接与发布时间，保存对应成品快照；反馈记录观察时间和实际数据，未填写保持空值。读者问题可“另建选题”，带回原文关联，不必进入独立复盘系统。

归档 OB 前预览目标目录、文稿与附件；保存为独立记录，路径冲突提示另存，不静默覆盖。失败留在当前内容重试，附件失败不宣称整套归档成功。

**验收场景**：导出后平台仍未发布；登记后改正文，已发布快照不变；归档失败不删除工作台内容或原笔记。

### 4.6 优质信源收藏到 OB

原型入口：[信源](http://127.0.0.1:8098/index.html#sources) → 查看详情 → 收藏 OB；收藏完成后可查看笔记、用于创作。

![收藏表单与失败保留](assets/learning-collect-2026-10-15.png)

RedFox、AIHOT、乔木 RSS 都是外部信息来源，不是选题结论。详情先展示来源、发布时间、原文链接、摘要和可获取的互动数据；来源未提供的字段明确留缺，摘要不冒充全文。RedFox 原热榜、搜索、评论、追踪和收藏动作不变，新增“收藏 OB”与原快速收藏并列。

| 收藏字段 | 展示与规则 |
|---|---|
| 笔记标题 | 默认材料标题，可修改 |
| 原文链接 | 沿用来源链接；模拟资料允许留空并标明演示来源 |
| 收藏理由 | 本人填写，不预填假装本人观点的样例 |
| 保存内容 | 选择摘要或选定摘录，可修改，不默认抓取全文 |
| 目标目录 | 预览新笔记位置；目录冲突另存，不覆盖原笔记 |

确认后生成独立来源笔记，包含出处、发布时间、采集时间、待核验标记、所选内容和收藏理由。已存的同一来源或同一原文链接返回已有笔记，不重复创建。写入失败保留表单，不显示成功；写入后的笔记在知识库按“OB 收藏”可查，支持引用和导入正文。

**本页验收**：收藏失败可原位重试；收藏后在知识库找到同一笔记；引用到新稿后来源和本人理由仍在，原始信息不被改成亲测结论。

### 4.7 从新闻形成可写的角度

原型入口：信源或知识库 → 用于创作 → 新建内容；编辑器中可以继续“编辑角度”。

新建时允许只存一句选题，也提供可跳过的三个问题：“读者问题”“内容角度”“待补证据”。它们跟随同一内容，不新建选题评估页面，不生成没有依据的推荐分数。选择已有内容时只加引用，不改变此前的角度。

例如，把“某 AI 工具更新”转成“第一次用 AI 整理会议纪要，如何核对漏掉的待办”。新闻是事实来源，自己的实测是独立证据；未经测试的结论保持待验证。生成前展示角度和所选材料，正文候选明确提示缺少的操作、结果和截图。

**本页验收**：保存选题后可原地补充角度、引用 OB 积累并建立平台稿；下一次打开仍保留这些判断；不填写角度也能手写，不强制完成问卷。

### 4.8 个人文风：改稿经验到下一篇写作

原型入口：[内容编辑](http://127.0.0.1:8098/index.html#editor) → 复盘修改；管理入口为知识库 → 我的文风，不新增左侧一级模块。

![修改对照与偏好确认](assets/learning-revision-2026-10-15.png)

![下一篇写作前确认使用](assets/learning-context-2026-10-15.png)

| 阶段 | 操作与反馈 |
|---|---|
| 保留对照 | 采用初稿后形成基准；本人修改保留修改前后，不每次按键建立一条规则 |
| 复盘修改 | 展示前后全文，填写修改原因；分类为仅本篇调整、事实纠错、表达偏好、平台格式 |
| 保存经验 | 各类修改均可保存独立经验笔记；只有表达偏好可成为后续写作规则 |
| 确认偏好 | 本人写清规则，选择仅本篇、公众号、小红书、抖音图文或三平台通用，明确勾选后启用；默认仅本篇且不启用 |
| 使用偏好 | 下一次生成前列出适用的已启用规则、来源稿件和确认时间；可逐条取消，不改长期设置 |
| 结果核对 | 候选保留本次选定规则；采用后可以回查，不显示无法验证的“文风匹配率” |
| 停用调整 | 在我的文风停用；之后新任务不再带入，已生成候选与历史文章保持原样 |

表达偏好与来源资料分开传入：不能把参考博主的表达当成自己的文风。事实纠错与格式调整不自动泛化；未启用的偏好仅保存，不偷偷使用。已有规则可能相互冲突，启用新规则前展示同范围规则供本人检查；不自动判断语义冲突，不覆盖旧规则。重复的同范围规则阻止重复新增。

保留对照不等于自动学习。正式开发时，应将本人确认的偏好作为写作上下文，结合选定的示例与 Skills 使用，而非宣称已训练模型。经验笔记需保留来源稿件、平台、原因及时间；私有笔记和表达偏好不随代码上传 GitHub。

写作依据优先顺序：事实与平台约束不可被文风覆盖；本次明确要求优先于长期偏好，长期偏好优先于第三方方法的默认措辞。发现相反要求时由本人取消本次不适用项，不以“更像本人”为理由编造经历。正式开发仍需验证长期使用时的偏好冲突与改稿版本保留，原型不宣称自动识别所有语义冲突。

**本页验收**：改事实并尝试启用被拦截；改表达但未勾选启用不参与下一篇；确认公众号偏好后，新公众号任务可选用，小红书不自动使用；保存失败不丢对照，停用不改旧稿。

### 4.9 一次完整使用任务

1. 浏览三类信源，打开一条信息，检查出处与时效；不要求每条信息都收藏。
2. 值得长期复用的资料点“收藏 OB”，补充本人判断；也可直接用于创作。
3. 确认内容角度，加入相关 OB 笔记，在同一内容建立公众号版本。
4. 选择写作方法，核对输入和适用文风，生成候选后采用；手动补真实证据、修改表达。
5. 复盘这次修改，经验存入 OB；只把确认的可复用表达启用为偏好。
6. 制作图片，核对正文与图页，预览并导出；人工发布后登记，成品另存归档。
7. 下一篇重新选材料和角度；生成前查看上篇积累的偏好，选择使用或不用。

这条链路以“完成一篇并让下一篇复用积累”为目标，不承诺三个月涨粉两万。实际效果需要用真实发布后的读者反馈验证。

## 5. Skills：完整可查，按任务使用

### 5.1 中心如何组织

默认按任务筛选：信息检索、选题整理、写作改编、标题开头、审稿检查、图片排版、知识归档。支持搜索具体名称和作者；来源、状态作为筛选，不按每位博主再建一个业务页面。

卡片显示能力名称、用途、来源和接入状态；详情补输入、产出、适用平台、版本、许可声明、运行依赖和最近验证范围。提供“常用”标记，但不隐藏完整目录。社区更新、自定义、模板与绑定保留在中心管理区。

状态分开表达，不混成一枚“可用”标签：

| 维度 | 显示规则 |
|---|---|
| 来源收录 | 文件存在只说明已收录；没有文件说明待安装或来源缺失 |
| 工作台接入 | 有明确调用入口和结果回填才标已接入；否则待接入 |
| 运行条件 | 当前检查缺登录、依赖或配置时说明原因，不沿用旧成功记录 |
| 实际验证 | 展示验证日期、具体任务和结果；没有记录标未验证 |

待接入能力仍可查看详情与交互计划，不提供假执行按钮。原型演示候选必须标“模拟结果”，不得写“真实生成成功”。同一 Skill 支持多项动作时展示关联关系，不能把动作数当独立 Skill 数量。

### 5.3 已安装但待接入的补充能力

不把本机全部 Skills 暴露成创作工具。下列是本轮核对到的内容相关方法，完整调用规则须在后续适配前审查；本表规定产品位置，不声称已接入。

| 方法 | 产品位置与边界 |
|---|---|
| 花叔选题、素材搜索 | 选题整理、参考材料；结果保留来源，不另设素材工作台 |
| 花叔校对、公众号配图 | 审稿检查、配图；与现有方法并列可选，不默认连续跑所有方法 |
| 花叔女娲 | Skills 中心的个人方法配置；用于定制方法，不当自动学习或涨粉引擎 |
| humanizer-zh | 表达检查的可选方法；保留本人事实与判断，不制造假经历 |
| 宝玉文章插图、信息图 | 配图中的插图与信息图用途；复用当前内容图片管理 |
| 云舒写作助手 | 写作改编的可选方法；现有个人写作助手保持独立且不覆盖 |
| thought-mining | 选题整理；从本人零碎想法整理观点，确认后存选题或加入当前稿 |
| image-render | 配图中的风格与逐图计划；检查运行条件后再接实际出图 |
| case-radar | 参考材料中的案例检索；依赖未满足时说明，不伪造案例和截图 |
| readable-output | 长文阅读预览的候选辅助；不是公众号后台发布排版 |

乔木 RSS 属于信源连接，不因出现在研究清单就伪装成写作 Skill。页面设计、测试文档等开发辅助 Skills 留在开发环境，不挤进用户的创作工具栏。第三方方法更新需显示来源版本、差异和许可声明；个人笔记、写作规范与密钥不随项目同步到 GitHub。

## 6. 原型修订范围与评审顺序

1. 先评审本文的功能归属、内容关系和 Skills 覆盖；不用视觉样式掩盖缺失的业务动作。
2. 修订交互原型：三个主入口、同一编辑器、多材料转入、Skills 选择与候选采用、图片失败恢复、成品与归档。沿用现有组件，不先换皮肤。
3. 用真实操作任务走查：从 RedFox 热点、OB 笔记、手写选题、已有文章分别开始；每条路径都能找到平台正文与成品。再验证旧功能入口及异常。
4. 交互确认后再做视觉统一和壁纸选择；内置壁纸点击应用，支持撤销、刷新保留，背景不进入导出图片。
5. 设计确认后才实现正式功能与迁移；先备份，再做新旧功能回归和真实任务验收，按实际完成范围同步 GitHub。

原型已将重复导航合并，并逐项展示登记能力与待接入方法；辅助管理路径仍有缺项，具体以本轮验收为准。不宣称已经修复正式系统的登录、生成或平台输出问题。
