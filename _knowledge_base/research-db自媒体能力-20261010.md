# db 自媒体能力专项核验

状态说明：下文保留开发前的调研记录；第一批适配已在后续开发上线，当前功能与验收结果见[开发记录](../docs/开发任务-db创作助手-2026-10-10.md)。

调研日期：2026-10-10。
目标：补足此前只强调标题与内容检查的筛选，按自媒体完整流程盘点 dontbesilent 的公开仓库与当前能力。

## 已知场景

账号为点灯的曾曾，面向 AI 职场小白，女生友好但不限性别；公众号、小红书、抖音图文优先，每周 18～22 小时。本轮只核验并调整方案，不安装能力、不改生产代码、不自动发布内容。

## 核验问题

1. dontbesilent 当前公开了哪些非 Fork 仓库，哪些真正属于自媒体能力？
2. 哪些能力对应定位、选题、标题、正文、审稿、对标、复盘和商业化？
3. 能力是否有当前 Skill 文件、原始材料、依赖和许可说明？
4. 现有工作台该直接保留、适配、延期或排除哪些能力？

## 发现

### 第一轮：仓库与当前能力范围

- GitHub API 返回 dontbesilent2025 当前三项公开非 Fork 仓库：dbskill、claude-skills、extract-getnote-articles。用户所说“很多能力”主要应按仓库内的 Skill 与方法包盘点，不能只看独立仓库数量。读取日期：2026-10-10，来源：https://github.com/dontbesilent2025 。
- 当前 dbskill 中文 README 包含内容创作、风险检查、共鸣诊断、内容价值、内容系统、理论核验等能力，先前方案只强调标题与内容价值，覆盖偏窄。来源：https://github.com/dontbesilent2025/dbskill 。
- 检索中不同语言 README 和新手文档存在数量与旧入口差异，不能依靠搜索摘要判断当前版本；下一步固定提交后核对正式能力清单。
- README 写个人使用、学习、研究与非商业项目可直接使用，商业用途另行授权。应区分“可研究与试用”“可接入商业生产”两种情境，不一概排除，也不扩大许可。来源：https://github.com/dontbesilent2025/dbskill/blob/main/LICENSE 。

### 证据范围

本轮以作者原仓库、固定提交下的 Skill 和许可文件为主要证据；它们可以证明能力的设计用途，不能证明在本账号上的实际效果。详细来源和阅读范围见文末。

### 第二轮：固定版本、正式清单与本地接入

- 上游 main 当前提交为 `564a794ffa8d08eb9c28ede8b2446237c1f67ada`，版本 2.18.47，提交日期 2026-10-08；本地 `skill-sources/dbskill` 为同一提交。已经下载最新源码，不需要为了本轮核验再更新源仓库。
- 当前 README 与 Marketplace 正式清单一致：34 个当前业务 Skill、2 个旧版兼容入口、1 个系统更新入口。本轮依当前提交判断，搜索缓存中的 32／33 个不能用作最新数量。来源：https://github.com/dontbesilent2025/dbskill/blob/564a794ffa8d08eb9c28ede8b2446237c1f67ada/.claude-plugin/marketplace.json 。
- 扫描本地全部 37 个 Skill 的用途声明后，发现对标、受众任务、内容组织、共鸣、传播机制、风险检查、公众号排版、内容系统与知识库导航都有对应能力。源码存在与工作台可调用不是同一个状态。
- 现有工作台能力目录仅暴露 db 的 `dbs-content-value` 与兼容旧入口 `dbs-hook`。主要短板是适配范围，不是缺最新源码；标题应改用当前 `dbs-title-cover-intro`。本轮未执行这个迁移。
- `claude-skills` 当前为拉康对话、定向聊天室和宠物，不是额外图文生产工具箱。README 写 MIT，但根目录列表未见独立 LICENSE；不按 API 的空许可或 README 单句直接完成代码复用许可审查。来源：https://github.com/dontbesilent2025/claude-skills 。
- `extract-getnote-articles` 是 Get 笔记文章导出工具，依赖登录、订阅和浏览器自动化，不是现有 OB 接入的必需组件；README 自述“合法”不能替代访问条款与素材授权核查。本轮不运行安装脚本、不登录或导出用户知识库。来源：https://github.com/dontbesilent2025/extract-getnote-articles 。
- 已读根 LICENSE：CC BY-NC 4.0，商业用途需要另行授权。这里的边界应明确保留，不据此否定研究、学习和经许可的使用。读取日期均为 2026-10-10。

### 第三轮：重点内容能力的实际边界

- 完整读取 `dbs-content`、`dbs-jtbd`、`dbs-resonate`、`dbs-benchmark`、`dbs-spread`、`dbs-ai-check` 和 `dbs-content-risk-check`。内容组织、读者任务、原句共鸣修改与传播复盘确有不同职责，不能合并为一个泛泛“内容打分”。
- `dbs-content` 明确是制作诊断而非代笔；应由它给创作方向，正文交写作能力。上游将“先有付款产品”“抖音变现靠投流”等作者观点放在规则中，不照搬为新手创作门槛或平台事实。
- `dbs-benchmark` 提供可执行路径比较，但还包含利润估算、固定流量阈值、像素级模仿与排除个人偏好的主张。仅适配作品结构、获客与交付链的观察方法，保持本人定位与知识产权边界，不猜博主利润。
- `dbs-resonate` 适合指出原句的共鸣断点；`dbs-spread` 适合解释已有作品的传播机制。二者都明确不能预测平台指标。实际受众反应须由评论、访谈或行为数据验证。
- 发布风险检查区分词面误伤与内容实质，给局部修改，明确不能保证通过审核；平台当前规则需另查官方来源。适合做发布前辅助，不作为法律合规或平台安全认证。
- 已读内容系统与知识库的核心段落：前者面向已有大量资产的重工程，后者保留既有目录、建立导航与版本关系。优先考虑知识库导航与现有 OB 接入协同；内容系统先保留候选，不因用户粉丝少就猜测其 OB 素材也少，更不擅自搬动整个库。
- 已读公众号 HTML 的兼容性核心规则：内联样式、稳定布局和防重复标题，能作为 gzh-design 的对照候选，不同时建设两套默认排版流程。视频提取需要 TikHub／轻抖凭证，视频导航需要字幕、字体与 FFmpeg 等；两者延期到对应视频任务，不默默新增费用。

### 阶段摘要（第 1 轮）

用户判断有依据：db 应升级为自媒体判断与诊断的主要候选层，而非只保留标题与内容价值。图像制作仍由 Codex＋图文编排能力承担，正文由专门写作能力承担；每次按任务择项调用，不让 34 个 Skill 全部运行一遍。当前只完成源码与适配范围核验，未做接入或效果实测。

## 调研结论

### 关键事实

1. db 的自媒体能力不只标题与开头，主要集中在 dbskill 的 34 个当前业务 Skill 中，另有 2 个旧版兼容入口与 1 个更新入口。固定版本为 2.18.47，提交日期为 2026-10-08。[当前能力表](https://github.com/dontbesilent2025/dbskill/blob/564a794ffa8d08eb9c28ede8b2446237c1f67ada/README.md)。
2. 工作台已保存同一版本的源码，但当前创作入口只适配了内容价值检查和旧版标题开头建议。因此，“源码已下载”不能显示成“全部可用”。证据为本地能力目录和任务说明，核验日期为 2026-10-10。
3. 作者提供的是用途不同的方法与流程，不是每篇都应完整运行的流水线。内容组织不能代替成稿，内容价值不能代替事实核验，共鸣诊断不能代替真实读者反馈。

### 推荐接入范围

以下均为适配建议，尚未新增可调用入口。

| 用户任务 | 对应能力 | 本项目保留的方法 | 接入边界 |
|---|---|---|---|
| 找到读者问题 | dbs-jtbd | 将泛泛人群描述转成情境、任务与阻力 | 读者需求先作假设，须由访谈、评论或实测补证 |
| 决定怎么制作 | dbs-content | 内容任务、表达形式和信息组织诊断 | 不承担代笔，不要求新手先有付费产品 |
| 确定标题承诺 | dbs-title-cover-intro | 标题、封面、开头与正文兑现一起判断 | 替代旧 dbs-hook；不编收益数字，不预测爆款 |
| 判断读者所得 | dbs-content-value | 分开看停留、收藏、分享和关注理由 | 保留现有适配，不把价值检查当事实核验 |
| 修改共鸣断点 | dbs-resonate | 对具体原句提出保留、删减或加强建议 | 不冒充受众实测，不覆盖已经确认的手改 |
| 检查自然表达 | dbs-ai-check | 定位空话、重复和体裁不合适的表达 | 可选检查；不输出“AI 率”，不照搬长问卷 |
| 发布前辅助检查 | dbs-content-risk-check | 区分词面问题与内容实质，给最小修改 | 不能保证过审，当前平台规则另查官方来源 |
| 学习优秀作品 | dbs-benchmark | 拆解任务、作品结构与行动路径 | 不猜博主利润，不抄作品，不忽略本人定位 |
| 分析作品反馈 | dbs-spread | 将传播机制解释与后续尝试分开 | 不预测点击、推荐或涨粉，缺数据不当零 |
| 找回 OB 材料 | dbs-knowledge | 导航、原文读取、来源和版本关系 | 只在用户选择范围内索引，不重排或搬迁整库 |
| 对照公众号排版 | dbs-wechat-html | 内联样式、正文不改写和预览检查 | 与 gzh-design 比较后选一个默认流程，需实际粘贴验收 |
| 核对观点依据 | dbs-theory-grounding | 先审主张、核对理论来源、说明适用条件 | 不替代新闻与产品事实检索，不照搬离线限制 |

第一批优先验证读者问题、内容组织、当前标题入口、共鸣修改和发布检查；现有内容价值检查继续保留，自然表达检查按需使用。第二批再验证对标、传播复盘、知识导航、排版对照与观点依据，避免一次增加过多操作。

`dbs-content-system` 留作已有素材工程的候选，先审计用户选定的素材范围与数量，不将上游数量门槛变成产品强制条件。视频提取与视频导航延期到视频任务；第三方凭证、费用、字幕和本地工具需要单独核验，它们也不等于完整视频生成。其余经营、行动和商业判断能力在对应问题出现时再择项使用，不塞进日常写稿必经流程。

### 待确认问题

- 新适配是否让本人更容易选题、减少改稿，需用真实样稿对照验证，不以安装数量验收。
- 本人 OB 的选定素材范围与规模尚未审计，不能据粉丝量推断素材量。
- 未来用于商业生产时需按非商业许可另行处理授权；本轮研究与规划不是商业接入许可确认。
- 公众号排版粘贴、平台当前规则、视频第三方依赖与费用均未完成实际验收。

### 后续创作与产品建议

db 作为读者判断、内容诊断和运营复盘的主要候选层，卡兹克等写作能力负责成稿，Codex 与宝玉、归藏的方法负责图片与编排。用户只操作“选题／写稿／审稿／配图／导出”，Skill 中心展示来源与状态，每次按任务选择必要的方法，不跑全套能力。女娲用于归纳经本人确认的方法，不用来替代所有生产步骤。
