# 图文创作能力调研笔记

状态说明：下文为开发前的调研记录；后续已上线 db 第一批助手适配，范围与验收结果见[开发记录](../docs/开发任务-db创作助手-2026-10-10.md)。其他候选能力仍按调研结论分批验证。

调研日期：2026-10-10
调研目标：为「点灯的曾曾」规划可持续改善的图文创作链，先研究再开发。

## 已确认背景

- 目标读者：AI 职场小白，女生友好但不限性别。
- 平台：公众号、小红书、抖音图文；本轮不扩展视频。
- 资源：每周 18～22 小时，三个平台起点合计 50 粉丝。
- 基础：现有个人工作台、Obsidian、本机 Codex 写作与原生生图。
- 90 天增长目标用于实验，不作为工具效果承诺。

## 关键问题

1. 花叔、卡兹克、归藏、乔木及其他作者的哪些公开能力适合各个环节？
2. 女娲是内容生产基础、方法提炼基础，还是两者都需要边界？
3. 如何让选题、标题、正文、配图通过共同验收，而非拼接提示词？
4. 如何将 OB 中的真实素材和人工修改转成可审查的学习资产？
5. 如何验证吸引力、自然表达和可复现价值，不伪造爆款与 AI 检测分数？

## 研究口径

优先读取作者原仓库、实际 Skill 文件和官方文档；区分公开声明、已读源码、工作台现有能力和待验证的建议。仓库活跃、星数或作者自述不代表实际效果。只做调研和规划，不安装新能力、不修改生产服务、不发布内容。

## 发现

### 第一轮：作者原仓库发现

- 花叔女娲的定位是「调研 → 思维模型提炼 → 生成人物／主题 Skill」，不是图文排版或生图引擎。公开说明明确区分思维方法与简单模仿。适合作为方法提炼层的候选，尚不能据此证明涨粉或写作提升。来源：https://github.com/alchaincyf/nuwa-skill ，读取日期：2026-10-10。
- 卡兹克写作明确有个人口吻与禁忌词，含四层自检。我们应学习审稿方法，不能把作者口吻、经历当作曾曾自己的表达。来源：https://github.com/KKKKhazix/khazix-skills/blob/main/README.md ，读取日期：2026-10-10。
- 归藏的社交卡片与材质插画是两个互补能力：前者整页编排，后者概念解释配图。我们当前只有固定文字卡片适配，不能宣称等同于完整上游的图片编排能力。来源：https://github.com/op7418/guizang-social-card-skill 与 https://github.com/op7418/guizang-material-illustration ，读取日期：2026-10-10。
- 乔木搜索命中 meta-skill，可继续检查是否适合路由／质量规范，而非将它误当成内容写作引擎。来源：https://github.com/joeseesun/qiaomu-meta-skill ，读取日期：2026-10-10。

### 第二轮：扩大作者目录核验

- 已通过 GitHub API 读取四位作者的非 Fork 公开仓库目录，不仅按已安装列表筛选。卡兹克另有 `human-writing` 通用中文写作能力；这比直接采用其个人写作身份更值得重点比较。来源：https://github.com/KKKKhazix/human-writing ，读取日期：2026-10-10。
- 花叔另有 `tramstop-skill`（真实素材注入与去模板表达）、`darwin-skill`（评估、改进、测试、保留／回滚）、`huashu-gpt-image` 与 `huashu-slide-codex`。目录说明只能证明项目定位，仍需逐项读取实际规则；不要据“自进化”名称推断会自动学会用户偏好。来源：https://github.com/alchaincyf ，读取日期：2026-10-10。
- 乔木 `qiaomu-writer` 将联网调研、写作、配图和手改反馈结合，但当前公开 README 指向 Seedream MCP 和作者自有知识库目录；不能原样接到我们的 Codex＋OB。来源：https://github.com/joeseesun/qiaomu-writer ，读取日期：2026-10-10。
- 归藏作者目录中有 `Humanizer-zh`；适合作为表达异常检查候选，而不是证明作者身份或判定“非 AI”百分比的仪器。来源：https://github.com/op7418/Humanizer-zh ，读取日期：2026-10-10。
- 本机旧 `huashu-proofreading` 与网页命中说明含“AI 检测率低于 30%”及作者个人素材路径；这一承诺不纳入我们的验收，应使用读者盲审、事实与修改成本。来源：https://github.com/alchaincyf/huashu-skills/blob/master/huashu-proofreading/SKILL.md ，读取日期：2026-10-10。

### 第三轮：正文与持续改进的关键分工

- `human-writing` 当前 README 标示 1.1.0：强调材料门槛、段落推进、自然中文和审稿；检查脚本只查硬规则，不代替判断文笔。它更适合通用正文基础，仍须用曾曾自己的稿件验证。来源：https://github.com/KKKKhazix/human-writing ，读取日期：2026-10-10。
- `tramstop-skill` 重点为真实素材与个人判断；作者发布了小规模对照盲测，不能把该实验结果当成我们账号或女性读者的普遍证据。我们采纳“真实经验不可编造”的机制，不采用其检测率或读者识别率承诺。来源：https://github.com/alchaincyf/tramstop-skill ，读取日期：2026-10-10。
- `darwin-skill` 公开定位正好对应持续改善：先评估再改进，用测试决定保留或回滚。它与女娲用途不同；我们需要固定样例、人工审批和可回退版本，而不是每篇自动改写全局 Skill。来源：https://github.com/alchaincyf/darwin-skill ，读取日期：2026-10-10。

### 阶段摘要（第 1 轮）

基础能力应分为证据、创作、交付和改善四层；作者身份不能被写进用户稿件。核心路线是通用写作＋真实素材＋图片编排，女娲负责方法提炼，达尔文负责受控评估。视觉面向明确读者场景，性别不直接决定配色。以上均为规划判断，尚未完成新能力的安装或实测。

## 补充发现

### 第四轮：补充作者与标题入口更新

- 宝玉的图卡、封面和插图能力分工明确；公开生图文档包含运行时原生后端。因此采用这些方法不意味着必须购买另一套生图 API。来源：https://github.com/JimLiu/baoyu-skills/blob/main/docs/image-generation.md ，读取日期：2026-10-10。
- db 当前统一入口为 `dbs-title-cover-intro`，旧 `dbs-hook`、`dbs-xhs-title` 已标记弃用。该能力分开处理发布标题、封面文字和开头，强调正文兑现承诺；不负责实际封面图片、不保证点击率。现有工作台仍引用锁定版旧入口，不能把上游更新视为已升级。来源：https://github.com/dontbesilent2025/dbskill/blob/main/skills/dbs-title-cover-intro/SKILL.md ，读取日期：2026-10-10。
- db 当前采用非商业许可；用户有商业化方向，不能将“个人账号”自动认定为允许商业使用。第一版生产路径应优先使用可许可能力或自行设计的内容检查，必要时另取授权。此为依赖风险提示，不是法律合规结论。

### 第五轮：实际规则、许可与迁移边界

- 已读 `human-writing/SKILL.md` 全文。保留材料门槛、事实边界、段落推进；其标点及句式硬禁令属于上游风格规则，不直接当作曾曾全平台默认。该 Skill 明确不建立长期作者规则库，因此长期偏好应另由用户确认的 OB 记录维护，不混进通用正文能力。
- 已读 `tramstop-skill/SKILL.md` 全文。保留真实经验、反过度编辑和照顾外行的结构服务，不照搬作者小样本实验数字。文章不需要故意“写不完美”或制造无关细节。
- 已读 `qiaomu-writer/SKILL.md` 全文。手改前后差异可提炼规则，但正文带作者口吻、固定知识库路径与 Seedream MCP；本产品只借鉴反馈机制，不能原样启用“零确认全自动交付”。全部配图失败时只能交文字草稿，不能标为图文完成。
- 已读 `qiaomu-meta-skill/SKILL.md` 全文。其职责是创建、评估、治理和发布 Skill，而非写一篇文章；参考其能力边界、版本、安装和评估证据标准，不增加日常创作步骤。本轮未执行其脚本、创建 Skill 或发布流程。
- 已读固定提交的 `darwin-skill/SKILL.md` 全文。新旧版本同条件比较、人工关口和可回退机制值得采用；模型评委不是读者，结构分不是内容效果。本轮不执行优化循环，不采用作者自述的论文数字与得分承诺。
- 归藏材质插画仓库根目录未见 LICENSE，GitHub 未识别许可。公开可读不代表授权直接复制，暂列方法参考，接入前须确认许可。来源：https://github.com/op7418/guizang-material-illustration ，读取日期：2026-10-10。

### 第六轮：OB 官方能力与当前工作台核对

- Obsidian 官方 Bases 可用本地 Markdown 与笔记属性形成列表／卡片视图；适合素材、选题和复盘检索，不需要为基础看板再叠多套数据库插件。来源：https://obsidian.md/help/bases ，读取日期：2026-10-10。
- 官方 Web Clipper 适合保存网页、标注和来源。Interpreter 是另行配置的模型处理功能；启用后页面上下文发送给所选模型，不能因为笔记存本地就称整个创作链不外发。首版采集模板不强制开启 Interpreter。来源：https://obsidian.md/help/web-clipper 与 https://obsidian.md/help/web-clipper/interpreter ，读取日期：2026-10-10。
- 静态核对工作台：已具备各平台稿、原生生图任务、锁定来源、显式关联 OB 笔记和独立归档；现有归藏适配是文字卡片，公众号正文仍参考个人卡兹克写作入口。没有证据证明目前已形成经过样稿验证的曾曾文风、素材充分性门槛、标题封面承诺检查及图文阅读质量闭环。
- 当前 OB 关联只提交明确选中的笔记，原笔记变化会阻止继续生成；这些安全边界应保留。来源：本地 `lib/workbench.js`、`lib/creator-capabilities.js`、`lib/workbench-obsidian.js`、`lib/creator-delivery.js`，检出提交 775cf8214ac7fe3e97605f7c3212065a180a8cbc；本轮为静态检查，未做新能力运行验证。

### 阶段摘要（第 2 轮）
